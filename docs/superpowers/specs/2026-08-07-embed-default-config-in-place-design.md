# Embed the default config in place (fixes #405)

Date: 2026-08-07
Issue: https://github.com/getplumber/plumber/issues/405

## Problem

`go install github.com/getplumber/plumber@v0.4.34` fails:

```
internal/defaultconfig/embed.go:18:12: pattern default.yaml: no matching files found
```

`internal/defaultconfig/embed.go` declares `//go:embed default.yaml`, but
`internal/defaultconfig/default.yaml` is git-ignored (`.gitignore:43`). It is
generated by a `cp` from `defaultConfig/.plumber.yaml` in every build path, so
local builds, CI and the release pipeline all succeed. The published module zip
never carries it, so every source install and every consumer that compiles the
module fails. `configuration` (a public package) gained the import in `17d3fdb`,
which pulled the broken embed into every consumer's build graph.

Binary releases are unaffected. Platform work that consumes `finding/identity`
is blocked until a release carries the fix.

Verified against the real artifact: the `v0.4.34` proxy zip contains
`defaultConfig/.plumber.yaml` (55217 bytes) and no
`internal/defaultconfig/default.yaml`. Dot-prefixed files ship in module zips
normally (`.gitignore`, `.dockerignore` and `.github/**` are all present).

## Approach

Embed the source file in place instead of copying it to a git-ignored location.
`//go:embed` cannot reach outside its own package directory, so the Go file
moves next to the YAML rather than the other way round. Confirmed by
experiment: a Go file declaring `//go:embed .plumber.yaml` in the same
directory as that dot-prefixed file compiles under Go 1.26.5.

The file stays at `defaultConfig/.plumber.yaml`. That path is a public
contract: `getplumber.io` publishes two copy-paste install commands that
`curl` it from `raw.githubusercontent.com`
(`src/docs/data/docs/en/cli/{github,gitlab}/index.mdx`), plus two prose links,
and the README, CONTRIBUTING, `templates/plumber.yml` and the file's own header
all point at it. Moving it breaks instructions already pasted into user
runbooks.

Rejected alternatives:

- **Commit the generated copy.** Un-ignore `internal/defaultconfig/default.yaml`
  and commit it. Smallest change, but it mirrors 55KB of YAML in git forever and
  every contributor has to remember `make embed` and commit both files.
- **Make the embed optional** behind a build tag or fallback constant. The issue
  notes this lets the discrepancy return silently.

## Design

### 1. Package layout

New file `defaultConfig/embed.go`, package `defaultconfig`:

```go
// Package defaultconfig embeds the shipped default Plumber configuration, the
// baseline every zero-config user gets. It lives beside the file it embeds
// because //go:embed cannot reach outside its own package directory, and
// embedding in place is what keeps the module self-contained: a generated
// copy elsewhere would have to be git-ignored or duplicated, and a git-ignored
// embed is exactly what broke `go install` (getplumber/plumber#405).
//
// The source is defaultConfig/.plumber.yaml, NOT the repo-root .plumber.yaml
// (which is Plumber's own self-scan config). The two are independent artifacts
// (getplumber/plumber#352): editing Plumber's self-scan config never silently
// changes the shipped default.
package defaultconfig

import _ "embed"

//go:embed .plumber.yaml
var config []byte

// Get returns the embedded default configuration as a byte slice.
func Get() []byte { return config }
```

`internal/defaultconfig/` is deleted. The 13 files that import it switch to
`github.com/getplumber/plumber/defaultConfig`:

```
cmd/analyze_gitlab.go          cmd/config.go              cmd/config_explain.go
cmd/config_resolve.go          cmd/config_resolve_test.go cmd/config_slim.go
cmd/config_slim_test.go        cmd/init.go                cmd/init_test.go
configuration/plumberconfig.go configuration/resolve.go   configuration/resolve_test.go
control/cache_poisoning_contract_test.go
```

The call surface is 38 calls, all `Get()`. The currently exported `Config` var
has zero uses outside its own package, so it becomes unexported and the new
package exports one function.

Accepted cost: the package directory is mixed-case and no longer under
`internal/`, so `Get()` becomes public API. That is one function returning
bytes. The alternative, keeping `internal/defaultconfig` as a forwarder, leaves
two packages named `defaultconfig` and exists only to hide the path.

Out of scope: `Get()` returns the shared backing slice rather than a copy.
Pre-existing behavior, unrelated to this bug.

### 2. Build-path cleanup

Nothing generates a file anymore, so every regeneration step is removed. There
are nine copies of `cp defaultConfig/.plumber.yaml
internal/defaultconfig/default.yaml` across the build paths, plus the comments
and `clean` rule that describe them:

| File | What goes |
| --- | --- |
| `.gitignore:42-43` | the ignore rule and its comment |
| `Makefile:6-12` | the `embed` target and its comment block |
| `Makefile` | `embed` as a prerequisite of `build`, `build-all`, `test`, `lint`, `deadcode`, `vuln`, `run`, `install` |
| `Makefile:69` | `rm -f internal/defaultconfig/default.yaml` in `clean` |
| `Dockerfile:25-26` | the `RUN cp` step and its comment |
| `Dockerfile:58` | the runtime-stage comment that points at "the cp into internal/defaultconfig above" |
| `.github/workflows/ci.yml:35,53,78,127` | "Prepare embedded config" in the `build`, `test`, `lint` and `govulncheck` jobs |
| `.github/workflows/codeql.yml:35` | "Prepare embedded config" |
| `.github/workflows/plumber-action.yml:38` | the `cp` line in its build step |
| `.github/workflows/release.yml:120` | "Prepare embedded config" |

Documentation follow-through. `CONTRIBUTING.md` references the embed in ten
places:

- `:113-120` the "always use `make build` instead of `go build`" rule. It
  exists only because of the embed, so it is dropped rather than reworded.
  (Line 120 is already stale today: it claims the copy adds a build header,
  which the current `cp` does not.)
- `:83`, `:930` `make build` in the setup and PR checklists. These stay, but
  no longer carry an embed implication.
- `:133-134` the make-target table loses the "Embed config +" prefix.
- `:234`, `:303` the repo tree diagram: `defaultConfig/` gains `embed.go` and
  loses the "(make build)" annotation; `internal/defaultconfig/` is removed.
- `:344`, `:622`, `:665`, `:818` the new-control checklist and release steps
  lose their `make embed` instructions.

`README.md` needs no change. All three of its links still resolve.

The doc comment currently on `internal/defaultconfig/embed.go` moves into the
new file, rewritten to describe embedding in place rather than the `cp`.

`.dockerignore` excludes neither `defaultConfig/` nor dot-prefixed files, so
the Docker build still sees the source. There is no `.gitattributes`, so
`git archive` exports the full tracked tree.

### 3. Tests

`cmd/init_test.go:TestEmbeddedDefaultMatchesSource` is deleted. It asserts the
embed is byte-identical to `../defaultConfig/.plumber.yaml`, which is
tautological once the embed is that file. Its purpose (catching a stale or
skipped regeneration) no longer exists, because there is no regeneration.

Unaffected and kept: `cmd/init_test.go:TestConfigGenerateMatchesEmbeddedDefault`
and `configuration/config_parity_test.go`, which read files from disk and do
not depend on how the embed is produced.

New job in `.github/workflows/ci.yml`, the actual regression guard:

```yaml
  clean-tree-build:
    name: Build from committed tree
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: actions/setup-go@b7ad1dad31e06c5925ef5d2fc7ad053ef454303e # v7.0.0
        with:
          go-version: '1.26.5'
      - name: Build from committed tree only
        run: |
          tmp=$(mktemp -d)
          git archive HEAD | tar -x -C "$tmp"
          cd "$tmp" && go build ./...
```

It compiles only what git tracks, so any git-ignored file that the build
requires fails it. It reproduces today's failure on the current `main` and
passes after the fix.

Considered and rejected: the issue's suggested `go install <module>@<sha>` into
a temp `GOMODCACHE`. It is a truer reproduction, but it needs the commit pushed
and visible to the module proxy, which adds latency and a network dependency
for the same class of catch.

### 4. Verification before merge

- The clean-tree build above, run locally: extract `git archive HEAD` into a
  temp directory and run `go build ./...` there. It must fail on `main` and
  pass on the branch.
- `go build ./...` and `go test ./...` with no `make embed` first, from a tree
  where `internal/defaultconfig/default.yaml` does not exist.
- `golangci-lint run ./...`. The package directory is mixed-case while the
  package name stays lowercase, so `ST1003` should not fire, but this is the
  one unverified assumption in the design.
- `make build`, `make test`, `make clean` still work with the `embed` target
  gone.
- `docker build .` succeeds.
- End to end, the binary behaves identically on a repo with no config, with a
  full config, and with a config that extends the default. This is the check
  that matters: every one of those paths reads `defaultconfig.Get()`, so a
  wrong or truncated embed would surface here and nowhere else.

  Run it differentially. Build binary `old` from the merge-base with
  `make build`, and binary `new` from the branch with plain `go build`. Every
  pair below must be byte-identical:

  | Config state | Command | Path exercised |
  | --- | --- | --- |
  | none | `config resolve` from a directory with no `.plumber.yaml` | zero-config fallback to the embedded default |
  | full | `config resolve -c <full config>` | full config, embedded default still forms the base layer |
  | extends | `config resolve -c <overlay with extends / includePlumberDefaults>` | overlay merged onto the embedded default |
  | n/a | `config generate` | must equal `defaultConfig/.plumber.yaml` byte for byte |

  `config resolve` needs no network and no token, so all four are
  deterministic. Then confirm the real analyze path once per config state with
  `plumber analyze --output`, diffing `old` against `new`:
  `getplumber/plumber-lab-github` has no `.plumber.yaml` (zero-config), and
  this repo's own root `.plumber.yaml` covers the full-config case. Author a
  throwaway overlay for the extends case.

## Risks and follow-ups

- **Mixed-case package directory.** Only real risk. Falsified or confirmed by
  `golangci-lint run ./...` in the first implementation step. If a linter does
  object, the fallback is keeping `internal/defaultconfig` as a forwarder so
  the import path never appears at call sites.
- **Lab repos carry the same pattern.** `plumber-inject-http-client` has the
  same `cp` in its Makefile and Dockerfile, and the other forks likely do too.
  Out of scope here. Worth a follow-up issue.
- **Release gating.** Platform stays blocked until a release ships. The commit
  is a `fix:`, so semantic-release cuts a patch on merge to `main`.

## Success criteria

1. `GOMODCACHE=$(mktemp -d) go install github.com/getplumber/plumber@<new tag>`
   produces a binary.
2. No file required by the build is git-ignored, enforced by CI on every push.
3. `defaultConfig/.plumber.yaml` is unchanged and still reachable at its
   current raw and blob URLs.
4. `plumber config generate` output is byte-identical to what v0.4.34 produces.
